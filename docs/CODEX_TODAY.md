# خطة اليوم (2026-10-26): وضوح المصانع والمزارع والمواشي + السلّم الوظيفي

**مصدر الطلب:** شكوى الجمهور: آلية المصانع (التشغيل، توظيف العمال، التصنيع)، وآلية المزارع (زراعة المواد، تربية المواشي، إضافة المواشي) غير مفهومة، ويحتاجون السلّم الوظيفي.
**قاعدة العمل:** دفعات صغيرة مرفوعة فوراً. الفحص بالطبقات (`docs/TESTING_BATCHES.md`): دخان + غرفة التعديل فقط؛ لا حزمة كاملة ولا قياس اقتصاد إلا إن مسّ التعديل أرقام الاقتصاد. اقرأ `docs/CODEX_MASTER_PROMPT.md` (الحالة والأولوية) أولاً.

## مبدأ واحد يحكم الكل: «بطاقة المتطلبات» لكل منشأة
لكل مصنع ومزرعة بطاقة واحدة تجيب بصرياً عن: **ماذا يلزم؟ ما الموجود؟ ما الناقص؟ وزر واحد يصلحه**، بدل أن يفتّش اللاعب بين الشاشات. صيغتها: قائمة بعلامات ✓ / ✗، وبجانب كل ✗ زر إصلاح مباشر (اشترِ، وظّف، انقل، اضبط)، وفي أسفلها سطر «ماذا يحدث بعد ذلك؟» (أين يذهب الناتج ومتى).

## المسار أ — المصانع والسلّم (Astra)
1. **بطاقة متطلبات المصنع** (أولاً): ✓/✗ لـ: المصنع مبني؛ المواد الخام في مخزن المدينة (المطلوب لكل دفعة / الموجود، مع «اشترِ الناقص» من سوق المدينة أو «انقل من القافلة»)؛ الأجور (من أين تُدفع، ومكتب المنطقة)؛ المدير (للمصنع في الخارج، بتوظيف مباشر؛ ومدير الممتلك بالترقية)؛ سعة المخزن للناتج؛ الجودة. ثم «الناتج يذهب إلى مخزنك؛ بِعه من هنا» وزر البيع.
2. **شرح التصنيع بسطرين** داخل البطاقة: «٢ بخور + ١ خشب ← ٢ عطر في الدفعة، وتتكرر كل يوم»، من `RECIPES` الفعلية (لا نص ثابت)؛ والأسعار الحية للمدخلات والمخرجات والربح التقريبي للدفعة.
3. **توظيف العمال في المصنع بالخطوات:** زر «وظّف عاملاً للمصنع» ينفّذ التوظيف الفعلي، ويعرض الأجر قبل التعيين.
4. **السلّم الوظيفي (٢١/ج مختصراً):** بطاقة «هرم الفريق» تعرض الرتب (عامل ← مدير ممتلك ← أمين المنطقة ← وكيل) ومن أنت فيها، وشرط الترقية التالية بعلامات ✓/✗ (أيام الخدمة، أجور نظيفة، الطور، عدد الممتلكات)، وزر «رقِّ» عند اكتمال الشروط. أمين المنطقة (رتبة ٣) بالحد الأدنى: ترقية مدير خدم ٩٠ يوماً، شروط الطور ٣ وثلاثة ممتلكات، دفع الأجور بتفويض، وتقرير. الوكيل (رتبة ٤) يبقى للدفعة التالية ولا يُعلن قبل أن يُنفَّذ.
**قبول المسار:** لاعب جديد يبني مصنعاً ويشغّله ويبيع ناتجه بالنقر على أزرار البطاقة فقط، في اختبار موجَّه جديد `factory-guided-ui` على ٣٩٠px.

## المسار ب — المزارع والمواشي (Sol للأول والثاني، Astra للثالث)
1. **بطاقة متطلبات المزرعة** (Sol): ✓/✗ لـ: المزرعة مبنية؛ مزارع موظّف؛ المرعى أو العلف؛ مواشٍ مضافة؛ سعة؛ ثم ماذا تُنتج (صوف، لبن، بيض، لحم) ومتى. أزرار: «وظّف مزارعاً»، «أضف مواشي».
2. **إضافة المواشي بخطوات «اختر ثم اشترِ»** (Sol، ملف ٢٠ بند ٨ وملف ٢٦ جزؤه الأول): شاشة واحدة لإضافة الماشية: اختر النوع والصنف (أصناف المدينة المسمّاة) ← الجنس والكمية بأسهم ← تكلفة وسعة ← «اشترِ وضعها في المزرعة» دفعة واحدة (أو «في القافلة»). تُظهر أين تذهب. وتُظهر الصنف في المزرعة والقافلة والمخزن وبطاقة المنتج.
3. **تربية المواشي مفهومة** (Sol): في المزرعة بطاقة «القطيع» بالجنس والصغار والحوامل ومتى الولادة، وسطر «كيف تتكاثر؟» بأرقام اللعبة (من `BREED`)، وزر «بِع/اذبح/انقل».
4. **الزراعة (محاصيل) — نسخة أولى مصغّرة (Astra):** لا تُبنى الآن كل ملف ٢٢. المطلوب اليوم: ٣–٤ محاصيل لكل دولة من جدول `docs/CODEX_TASKS_22.md` (حسب المنطقة)، زراعة بالنقر (اختر المحصول ← الأرض ← «ازرع»)، نمو بالأيام بمراحل، «احصد» يضع الغلة في مخزن المدينة، موسم زراعة مبسّط. **بلا** ري ولا أشجار ولا زكاة ولا مزارعين موسميين (للدفعة التالية). إن تأخر هذا البند يُكتب فوراً في المزرعة نص صريح: «الزراعة قريباً؛ المزرعة اليوم للمواشي»، ولا يُترك اللاعب يبحث عنها.
**قبول المسار:** اختبار موجَّه `farm-guided-ui`: ينشئ مزرعة ويوظّف ويضيف ماشية ويرى منتجاتها بالنقر على أزرار البطاقة فقط؛ وبعد المحاصيل: يزرع ويحصد ويبيع.

## المسار ج — حدود الحمولة والتخزين (عاجل، من شكوى الجمهور: قليلة جداً)

### الأرقام الحالية (من الشيفرة)
| العنصر | الآن |
|---|---|
| عربة واحدة | ١٠٠ وحدة حمولة؛ تُشترى بـ٦٠٠ ثابتة؛ **حدّها ٦ عربات لكل قافلة = ٦٠٠** |
| جمل أصيل (ركوب) | +٢٠٪ حمولة، بـ١٤٠٠ |
| مخزن | ٤٠٠ وحدة؛ تكلفته ١٢٠٠×١٫٤^عدد المخازن (تتصاعد بسرعة) |
| رفّ دكان | ٨٠ وحدة (+٢٥٪ لكل مستوى، مستويان فقط)؛ بسطة ٤٠ |
| الأوزان | الحديد ٣، الخشب ٢، الجمل والخيل ٣، البقية ١ (العطر ٠٫٥): **٢٦ وحدة حديد تملأ رفّ دكان كاملاً** |

### لماذا قليلة
1. حدّ ٦٠٠ ثابت لا يتطور مع ثروة اللاعب؛ ثروة بالملايين وحمولة ٦٠٠.
2. لا ترقية للعربات ولا للمخازن (فقط شراء المزيد)؛ والرفوف مستويان.
3. السلع الثقيلة (حديد، خشب، ماشية) تلتهم السعة، والواجهة لا تشرح الأوزان.
4. المخازن: تصاعد ١٫٤ يقتل الحافز عند المخزن الثالث.

### الحلول المقترحة (مرتبة بالأثر، وكلها صغيرة)
**أ) أرقام (أنا، فوراً، ثوابت):**
1. حدّ العربات **٦ ← ١٠**، وسعر العربة من ٦٠٠ ثابت إلى `٦٠٠ + ١٠٠×(عدد العربات−١)` ليبقى التوسع مكلفاً بلا سقف قاسٍ.
2. الجمل الأصيل **+٢٠٪ ← +٣٥٪**.
3. المخزن **٤٠٠ ← ٦٠٠**، وتصاعد التكلفة **١٫٤ ← ١٫٣**.
4. رفّ الدكان **٨٠ ← ١٢٠**، والبسطة **٤٠ ← ٦٠**.
5. بعد التغيير: قياس اقتصاد واحد (القطاعات والثروة والدكاكين + `measure-economy`) لأن الأرقام تمس الاقتصاد؛ إن ارتفع الدخل أكثر من المقبول يُخفَّف رقم واحد (لا كلها).

**ب) ترقيات (كودكس، مسار ج):**
1. **تطوير العربات:** ٣ مستويات بـ+٢٥٪ لكل مستوى على حمولة القافلة، بتكلفة ١٥٠٠ / ٣٥٠٠ / ٨٠٠٠ ولكل قافلة.
2. **تطوير المخزن:** مستويان بـ+٢٥٪ لكل مخزن، بتكلفة ٢٠٠٠ / ٤٥٠٠ (ولكل مدينة).
3. **رفوف الدكان:** إضافة مستوى ثالث بتكلفة أعلى.

**ج) وضوح (كودكس، مسار ج، الأهم للجمهور):**
1. شريط «الحمولة ٣٤٠ / ٦٠٠» في القافلة والسوق، بلون يتغير عند ٨٠٪ و١٠٠٪، وسطر «٣ وحدات حمولة للحديد».
2. وزن كل سلعة في بطاقتها («يشغل ٣ من الحمولة»).
3. عند الامتلاء: رسالة بسبب واضح وزر: «بِع الراكد»، «ابنِ مخزناً»، «اشترِ عربة»، «انقل إلى مخزن المدينة».
4. في المخزن والدكان: شريط سعة بنفس المنطق، وتنبيه قبل الامتلاء.
