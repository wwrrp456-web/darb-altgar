# خطة التنفيذ: كيف تُشغَّل الحزم

المرجع: `docs/MASTER_PLAN.md` (مسودة ٤). هذا المجلد فيه ملف لكل حزمة من م٠ وم١ والبوابة. **حزم م٢ فما بعدها تُكتب بعد `docs/PLAYTEST_1.md`.**

## لمن يقرأ هذا (Sonnet أو Codex)
اقرأ بالترتيب: `CLAUDE.md` ثم `src/README.md` ثم هذا الملف ثم ملف الحزمة المطلوبة. نفّذ **حزمة واحدة فقط** في الجلسة.

## قواعد ثابتة
1. **حزمة واحدة**، ثم توقف وأخبر بن محمود بما أُنجز وما يُعرض عليه.
2. **لا تعدّل** `src/engine.js` (مولَّد)، ولا أي صورة في `brand/img/`، ولا أي نص في `docs/review/APPROVED_*`، ولا نصاً دينياً أو حكماً شرعياً من عندك.
3. **الاختبارات:** أثناء العمل `node test/run.js --changed`. **قبل الدفع:** `node build.js` ثم `node test/run.js` كاملاً بلا إخفاق جديد. الإخفاقات المعروفة سابقاً مذكورة في WP-02؛ لا تُحسب عليك لكن لا تزِد عليها. اختبار تقلّب يُعاد مرة منفرداً قبل الحكم عليه.
4. **سجل التغييرات:** سطر في `docs/guide/CHANGELOG.md` بصيغة `- [لاعب|مبرمج] التاريخ: النص`.
5. **الدفع إلى `main`:** `git checkout -q -- docs/ui-audit` ثم `git add -A src test docs index.html sw.js version.json pwa guide img` ثم commit، ثم `git fetch origin main && git merge origin/main` ثم `git push origin HEAD:main`، ثم تحقق `git ls-remote origin main`.
6. **تعارض الملفات المبنية** (`index.html` و`sw.js` و`version.json` و`src/engine.js`): لا تحلّه يدوياً. اقبل نسخة المصدر المدموجة ثم شغّل `node build.js` وأضف الناتج.
7. **إن تعذّر شيء** (ملف ناقص، اختبار لا يُصلَح في نطاق الحزمة): توقف واكتب في `docs/plan/STATUS.md` ما وجدته بالضبط، ولا تختلق.
8. **لا تتجاوز نطاق الحزمة.** كل ملف حزمة فيه قسم «لا تلمس».
9. **عند الإغلاق:** حدّث `docs/plan/STATUS.md` (الحالة والتاريخ ورقم الالتزام).
