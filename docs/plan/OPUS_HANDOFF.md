## 1) الدور وطريقة العمل
- **بن محمود** (المالك) يقرر. **Opus** (هذه المحادثة): يخطط، ويكتب SpecKit أو مهام `docs/plan/EXEC_TASK_*.md`، ويراجع ما يدفعه المنفّذون، ويعطي **رسالة واحدة قصيرة جاهزة للنسخ لكل منفّذ**، ويوصي بتوصية واحدة.
- **التواصل:** بالعربية، مختصراً جداً، بلغة بسيطة («اشرح كأنك تشرح لطفل»)، توصية واحدة، وجداول قصيرة. **وفّر الحدّ**: مراجعة خفيفة (التقرير + اختبار أو اثنان مرتبطان + لقطة)، لا الحزمة الكاملة.
- **لا تُصلح ولا تُرسل شيئاً قبل النقاش** حين يطلب بن محمود النقاش. سجّل القرارات في `BM_PLAYTEST_NOTES.md` فور اتخاذها.
- **الأفكار الجديدة** تُسجَّل ملاحظة مرقّمة (الأخيرة **28**)؛ لا تنفيذ قبل اعتماده.
- **الدفع:** إلى `main` وإلى فرع المحادثة بعد `git fetch && git merge origin/main`؛ GitHub يعطي أحياناً Internal Server Error: أعد المحاولة. تحقّق من وصول عمل المنفّذ بـ`git ls-tree origin/main <path>` (حدث أن ظن منفّذ أن عمله دُفع ولم يُدفع).
- **مراجعة المنفّذ:** `git log HEAD..origin/main`، تقرير الحزمة، اختبارات الحزمة (`node test/X.test.js`)، لقطة 390. بعد الاختبارات: `git checkout -- docs/shots test/fixtures` لأن الاختبارات تعيد الالتقاط.

1. **مراجعة 032** (الازدهار) ثم إعطاؤه **033ب** (رسالة على نمط رسالة 033أ: SpecKit في `specs/033-page-order/` لجزئه فقط ثم تنفيذ، لكل تغيير مفتاح رجوع، لقطات 390 قبل/بعد).
2. **الأمين:** يقلب `TOPBAR.on=true` ثم 033أ (أُرسلت الرسالة؛ تحقّق).
3. **كودكس:** نماذج الخريطة الأربعة من `MAP_ART_BRIEF.md` (رسالتها جاهزة في المحادثة السابقة: «نفّذ docs/design/MAP_ART_BRIEF.md كما هو... وتوقف حتى يختار بن محمود»). وأيقونات تبويبات المكتب الأربع (لفافة، قبة، ريشة وختم، صرّة) تُضاف إلى `ART_NEEDED.md` من الأمين.
4. **المختص:** الدفعة `docs/review/batches/10-diwan-broker-rivals.md` (12 بنداً: PJ-01..04، DW-01، SH-01..04، RV-01..03) أُعطيت لبن محمود ليرسلها؛ حين يعود الرد: سجّله `docs/review/APPROVED_*` وطبّقه (M16/F13/G17 مخفية في 028؛ SH في 030؛ DW-01 في 025).
