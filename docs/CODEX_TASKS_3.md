5. قبل كل دفع: `git pull --rebase origin main`، وشغّل الاختبارات المعنية بمهمتك (للمهمتين ٤ و٥: اختبارهما الخاص، ثم `sh test/all.sh` كاملاً)، ولا تدفع إن فشل أي اختبار. الدفع إلى `main` مباشرة بلا PR.

7. إن تعارضت وثيقة قديمة مع هذا الملف فالمرجع هو هذا الملف ثم `brand/IDENTITY.md` ثم `brand/STYLE.md`.

اقرأ قبل البدء: `CLAUDE.md`, `DESIGN.md`, `docs/CODEX_ART_TASKS.md` (الأقسام ١–٥ والبند ٨: سطر الأسلوب الثابت والشفافية والأحجام)، و`brand/STYLE.md`, `brand/ICONS.md`, `brand/CHARACTERS.md`, و`brand/PROMPTS_GEMINI.md` (كتلة المشاهد).

## المهمة ٤ — وحدة الأصوات `src/sound.js` (شيفرة، ملف جديد فقط)

أصوات **برمجية بلا ملفات صوتية** وبلا موسيقى، تُحمَّل كمكتبة داخل صفحة اللعبة المبنية. تُكتب بنمط `src/icons.js` (دالة فورية IIFE تضع كائناً عاماً `Sound` ويعمل في المتصفح و`require` في Node).

**الواجهة المطلوبة (لا تغيّرها):**

```js
Sound.play(name)        // يشغّل صوتاً قصيراً؛ لا يرمي خطأ أبداً (لا صوت إن كان مكتوماً أو لا يوجد AudioContext)
Sound.setMuted(bool)    // يحفظ الحالة في localStorage بالمفتاح 'darb-mute' داخل try/catch
Sound.isMuted()
Sound.unlock()          // يستأنف AudioContext عند أول لمسة (يستدعيه المساعد من حدث نقر)
Sound.names             // مصفوفة بأسماء الأصوات المدعومة
```

**الأسماء المطلوبة:** `click`, `buy`, `sell`, `coin`, `success`, `fail`, `alert`, `levelup`, `caravan`, `haggleWin`, `haggleFail`, `tick`. كل صوت بين ٦٠ و٦٠٠ مللي ثانية، بمذبذبات وضوضاء وغلاف سعة، **منخفض الصوت** (أقصى سعة ٠٫٢)، لطيف ولا يزعج، بنَفَس شرقي بسيط حيث يناسب (مثلاً `coin` رنين معدني قصير، و`caravan` نقرات جرس خفيفة).

**القيود:** بلا أي اعتماد خارجي، حجم الملف ≤ ٨ كيلوبايت قبل الضغط، لا تستخدم أي واجهة غير موجودة في المتصفحات الحديثة على الجوال (يشمل Safari)، لا إنشاء `AudioContext` قبل `unlock()` أو أول `play()` بعد لمسة، و`Sound.play` يتجاهل الاستدعاءات المتكررة السريعة (حدّ أدنى ٣٠ مللي بين الصوتين نفسهما).

**الاختبار** `test/sound.test.js` (Node فقط، بلا متصفح): يمرّر `AudioContext` وهمياً ويتحقق من: عدم رمي خطأ بلا سياق صوتي، `names` تحوي كل الأسماء، الكتم يمنع إنشاء أي مذبذب، وحفظ الكتم في `localStorage` وهمي، وتجاهل الاستدعاء السريع، وأن كل اسم يُنشئ مذبذباً أو مصدر ضوضاء واحداً على الأقل. شغّله بـ`node test/sound.test.js`. **لا تعدّل `build.js` ولا `test/all.sh`**: المساعد البرمجي يضمّن الوحدة ويضيف الاختبار.

## المهمة ٥ — وحدة رمز الحفظ `src/savecode.js` (شيفرة، ملف جديد فقط)

تحويل حفظ اللعبة (نص JSON) إلى **رمز نصي** يُنسخ ويُلصق، وقراءته مرة أخرى، دون أي خادم. نمط الملف كـ`src/icons.js` (IIFE يضع كائناً عاماً `SaveCode` ويعمل في المتصفح وفي Node).

**الواجهة (لا تغيّرها):**

```js
SaveCode.encode(jsonString)  // → { ok: true, code: 'DT1-...' }  أو { ok: false, msg: 'عربي' }
SaveCode.decode(codeString)  // → { ok: true, json: '...' }       أو { ok: false, msg: 'عربي' }
```

**المتطلبات:**
- ضغط **مدمج في الملف** بلا مكتبات خارجية (خوارزمية بأسلوب LZ77/LZW تكفي) ثم ترميز base64url، وبادئة `DT1-` ورقم نسخة، ومجموع فحص (مثل CRC32 أو Adler) لاكتشاف الخطأ في النسخ.
- يتحمّل النص العربي (UTF-8) وكل ما يمكن أن يحويه حفظ اللعبة، ويُرجع **نفس النص حرفاً بحرف**.
- `decode` يتجاهل المسافات وفواصل الأسطر والشرطات الزائدة وأي أحرف في طرفي الرمز، ويرفض بخطأ **عربي واضح**: رمز فارغ، أو بلا البادئة، أو نسخة غير معروفة، أو مجموع الفحص خطأ («الرمز ناقص أو تالف»)، أو محتوى ليس JSON.
- حدّ أقصى معقول لحجم المدخل (٥ ميغابايت) مع رسالة واضحة، وأداء مقبول: ضغط حفظ بحجم ٥٠٠ كيلوبايت وفكّه خلال ثانية على جوال متوسط.
- لا يستعمل `CompressionStream` ولا `crypto.subtle` (لتعمل في كل بيئة).

**الاختبار** `test/savecode.test.js` (Node): جولة كاملة على `require('../src/engine.js')`: ينشئ لعبة (`E.newGame(5)` ثم ٦٠ يوماً بـ`E.tick`)، يأخذ `E.save(S)` ويرمّزه ويفكّه ويقارن حرفياً، ويتأكد من أن `E.load(decodedJson)` يعمل. ويختبر: حفظ فارغ، نص عربي كثيف، رمز مقطوع، رمز مغيَّر حرفاً واحداً، رمز بلا بادئة، مسافات وأسطر ملصقة في الرمز، وأن نسبة الضغط أقل من ٦٠٪ لحفظ حقيقي. شغّله بـ`node test/savecode.test.js`. **لا تعدّل `engine.js` ولا `build.js` ولا `test/all.sh`.**
