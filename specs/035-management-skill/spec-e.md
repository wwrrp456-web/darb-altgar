## 0) حقائق في الشيفرة (قرأها Opus)
1. **وكيل الإقليم بلا نمو اليوم:** `skillMigrate` يعطيه `sk` بدرجة 3 (ماهر) ولا يضيف `skillDay` إليه شيئاً. فالنمو يُكتب هنا (§2-أ). وبطاقة الكفاءة (`skillView`) تخطئ مفتاحه: `nk` يصير `'mgr'` لأن `ra.mail` موجود و`ra.budget` غير معرّف؛ يُصحَّح (§4).
2. **صافي المدينة الشهري موجود:** `pr.hist` (`19-player.js:103`) سجل يومي `{d, rev, net}` لآخر 30 يوماً، و`net` بعد تكلفة البضاعة والأجور والصيانة والإيجار ورسوم السوق. **أجر مدير المدينة** يُدفع بـ`payObligation(S,'staff',…)` (`13-factories.js:134`) فيدخل `Lx.staff` الذي يطرحه `pr.hist`. **أما أجر وكيل الإقليم** فيُدفع بـ`pPay(S,'regionalAgent',…)` (`24d:33`) فلا يدخل `pr.hist`؛ لذلك يُطرح صراحةً في §3.

## 2) وكيل الإقليم بالدرجات (T040)
### أ) النمو
في `ragDay(S)` (يُستدعى من آخر `skillDay` إن `RAG.on`)، لكل `country` في `P.regAgents` وفيه `ra.sk`:
```
cs        = stewardCitiesIn(S, country).slice(0, RA.span)
كل 7 أيام (S.day % 7 === 0):
   net    = Σ_{id ∈ cs} (shopPnl(S, id, 7)?.net ?? 0)          // متوسط صافي اليوم لكل مدينة، مجموعاً
   ra.sk.m = skM(net)                                          // 035أ: 1 + 0.6·tanh(net/150) مقصوصة إلى [0.6، 1.6]
كل يوم:
   skGrow(ra, 'a', ra.sk.m ?? 1, S, null)                      // xp += m × bonMul(ra, S) (انظر §3-و)؛ الدرجة لا تنزل
```
الدرجات من `SKILL.need.a`: يبدأ 3 (150 xp)، و4 عند 320، و5 عند 700. فالوكيل المعتدل (`m=1`) يبلغ 4 بعد 170 يوماً و5 بعد 550؛ والرابح (`m=1.6`) بعد 107 و344.
`ragGrade(ra) = RAG.on && ra && ra.sk ? clamp(ra.sk.g, 3, 5) : 3`. و`ragT(ra, key) = RAG[key][ragGrade(ra) − 3]`.

### ب) الدرجة 4 «يقارن المدن»
1. **الإنذار الأبكر** في `agentWeekly` (`24d:15–17`)، قراءة **وحدها** عبر `ragT`:
   | الموضع | اليوم | بعد 035هـ |
   |---|---|---|
   | `ra.neg[id] === RA.negWeeks` | 3 | `ragT(ra,'negWeeks')` (3 ثم 2 ثم 2) |
   | `bs.trust <= RA.trustWarn` | −30 | `ragT(ra,'trustWarn')` (−30 ثم −20 ثم −20) |
   والنص نفسه، يتغير فيه العدد وحده («تخسر منذ {n} أسابيع متتالية»).
2. **سطر المقارنة** يُلحق بالتقرير الأسبوعي (درجة ≥ 4، وعدد `cs` ≥ 2):
```
r_i   = alloc_i > 0 ? round(100 × net7_i / (7 × alloc_i)) : null     // عائد كل 100 ريال من الحد في الأسبوع؛ net7_i = shopPnl(S,i,7).total
best  = المدينة ذات أعلى net7_i ؛  worst = ذات أدناه (عند التساوي: ترتيب S.order)
النص: «الأفضل: {best} (صافي {net7/7}/يوم، كل 100 من الحد أعادت {r}) · الأضعف: {worst} (صافي …، …)» ؛ وr=null يُكتب «بلا حد»
```
3. **اقتراح النقل** (بطاقة «المطلوب»، مرة في الأسبوع على الأكثر لكل دولة، عند التقرير الأسبوعي):
```
الشرط: درجة ≥ 4 ، و r_best ≠ null و r_worst ≠ null ، و r_best − r_worst ≥ RAG.shift.gap (20) ، و net7_best > 0 ، و alloc_worst > 0 ، ولا ra.shift سارٍ بالمدينتين نفسيهما
البطاقة: id = 'rag:shift:' + country + ':' + floor(S.day / 7)
   «عائد الحد في {best} {r_best} وفي {worst} {r_worst}. أقترح نقل 10٪ من حد {worst} ({d} ريال يومياً) إلى {best} لمدة 28 يوماً.»
   d = round(alloc_worst × RAG.shift.k, 2)
   الخيارات: «انقل {d} ريال» ← A.ragShift(S, country, worst, best)  |  «لاحقاً» (تأجيل البطاقة 7 أيام، dsnooze القائم)
A.ragShift: ra.shift = { from: worst, to: best, k: RAG.shift.k, till: S.day + RAG.shift.days } ثم agentAlloc
```
   **أثره في `agentAlloc`** (بعد حساب `lim` لكل مدينة كما اليوم، وقبل الكتابة في `m.policy.limit`):
```
إن ra.shift && S.day < ra.shift.till && from ∈ cs && to ∈ cs:
   d = round(lim[from] × ra.shift.k × 100) / 100 ;  lim[from] −= d ;  lim[to] += d
وإلا: delete ra.shift
```
   **مجموع الحدود لا يتغير** (نقل لا زيادة). وزر «ألغِ النقل» في بطاقة الوكيل يحذف `ra.shift` (`A.ragShift(S, country, null)`).

### ج) الدرجة 5 «يقترح التوزيع والتمويل»
1. **التوزيع بالأداء** (اختيار يعرضه الوكيل مرة عند بلوغ 5، ويبقى زرّاه في بطاقته):
```
ra.mode === 'perf' (والدرجة 5):
   need_i = agentNeed(S, i) ;  pos_i = max(0, shopPnl(S, i, 7)?.total ?? 0)
   N = Σ need_i ;  Q = Σ pos_i
   share_i = N > 0 && Q > 0 ? RAG.perf.need × need_i / N + RAG.perf.profit × pos_i / Q
           : N > 0          ? need_i / N
           :                  1 / |cs|                       // كما اليوم
وإلا: share_i كما اليوم (need_i / N أو 1/|cs|)
lim_i = round(eff × share_i × 100) / 100                     // eff كما اليوم (نصف الحد في التجربة)
```
   البطاقة: `id = 'rag:perf:' + country`، «صار وكيلك شيخ الصنعة: أقترح توزيع حدّ الدولة 70٪ بالحاجة و30٪ بالربح. بهذا تأخذ {best} {lim_best'} بدل {lim_best}.» الخيارات: «وزّع بالحاجة والربح» ← `A.ragMode(S, country, 'perf')` | «أبقِ التوزيع بالحاجة» ← `A.ragMode(S, country, 'need')`. وفي بطاقة الوكيل زرّان بالحالة المختارة مظلَّلة (`on` + `aria-pressed`) وسطر الملخص بالأرقام (§4).
2. **اقتراح التمويل** (عند التقرير الأسبوعي، والدرجة 5، و`S.day − (ra.fundDay ?? −99) ≥ RAG.fund.gap`):
```
N    = Σ_{i∈cs} agentNeed(S, i)                                           // حاجة يومية
eff  = (ra.pool || 0) × (S.day − ra.since < RA.probation ? RA.probationShare : 1)
free = max(0, P.wallet.sar − operatingReserve(S) − (S.zakat && S.zakat.due ? S.zakat.amount : 0))
Z    = min( ceil(RAG.fund.over × N / 100) × 100 ,  floor(free / 7 / 100) × 100 )
الشرط: eff < N  و  Z > (ra.pool || 0)
البطاقة: id = 'rag:fund:' + country + ':' + S.day ؛ ra.fundDay = S.day
   «حاجة مناطقك {N} ريال يومياً وحدّك {pool}. أقترح رفعه إلى {Z}؛ يبقى احتياطي المستحقات والزكاة ({res}) لا يُمس.»
   الخيارات: «اجعله {Z}» ← A.agentPolicy(S, country, Z, ra.usd)  |  «لاحقاً»
```
   (`res = operatingReserve(S) + zakatHeld`). **لا يُرفع الحد إلا بنقرة اللاعب** (الفعل القائم `agentPolicy`)، والوكيل لا يملك أن يرفعه بنفسه (FR-004).

## 3) المكافأة الشهرية 5٪ (T041) — حساسة
### أ) المستفيدون والوحدة
| المستفيد | الوحدة | صافي الشهر `N` | النسبة | الأجر اليومي `w` |
|---|---|---|---|---|
| مدير المدينة `pr.mgr` (`rank` 2 أو 3)، **ليس** تحت وكيل | المدينة `city` | `Ncity(city)` | `rate` = 5٪ | `managerWage(pr.mgr)` |
| مدير المدينة في مدينة يشملها وكيل (`city ∈ cs` لوكيل دولتها) | المدينة | `Ncity(city)` | `rate × (1 − agentShare)` = 4٪ | `managerWage(pr.mgr)` |
| وكيل الإقليم `P.regAgents[country]` | مدن `cs` | `Nagent(country)` | `rate × agentShare` = 1٪ | `agentWage(S, country)` |
```
Ncity(city)     = Σ { h.net : h ∈ P.props[city].hist ، h.d > S.day − 30 }               // صافٍ بعد المصروفات وأجر المدير (§0-2)
Nagent(country) = Σ_{city∈cs} Ncity(city) − (ra.paid − ra.bon0)      // يُطرح أجر الوكيل المدفوع منذ الحساب السابق
                  ra.bon0 = ra.paid بعد كل حساب (§3-ب)؛ وإن ra.bon0 غير معرّف: ra.bon0 = ra.paid ولا يُحسب للوكيل هذا الشهر (لا لقطة سابقة)
```
**قاعدة الريال الواحد:** كل ريال صافٍ يُكافَأ عليه **مرة واحدة بـ5٪** في المجموع: في المدينة المشمولة بوكيل، 4٪ لأمينها و1٪ للوكيل. لا تراكم.

### ب) الحساب (كل 30 يوماً: `S.day % BON.every === 0`، في `bonDay(S)` من آخر `skillDay`)
لكل مستفيد `e` (بالترتيب: مدن `S.order` ثم الدول بترتيب `Object.keys(P.regAgents)`):
```
الأهلية: days(e) ≥ BON.minDays (30)                 // مدير المدينة: S.day − (e.since ?? (S.day − (e.days || 0))) ؛ الوكيل: S.day − ra.since
         و e.late == 0 (أو ra.late == 0)             // لا مكافأة لمن تأخر أجره ولم يُسدَّد (يُسدَّد أولاً)
         و لا paymentDue مفتوح له (S.paymentDues.some(d => d.id === e.paymentDue && d.amount > 0) = false)
raw  = share × max(0, N)                            // share = 0.05 أو 0.04 أو 0.01 من الجدول
cap  = BON.capMonths × 30 × w                       // سقف أجر شهرين
B    = floor(min(raw, cap))
free = max(0, P.wallet.sar − operatingReserve(S) − (S.zakat && S.zakat.due ? S.zakat.amount : 0))
offer= min(B, floor(free))
إن offer < BON.min (10): لا بطاقة، ويُكتب سطر في تقرير الشهر بالسبب:
     N ≤ 0 → «لا مكافأة لـ{الاسم}: صافي وحدته هذا الشهر {N}» ؛ B ≥ 10 و free أقل → «أجّلتُ اقتراح مكافأة {الاسم} ({B}) لأن الفائض فوق الاحتياطي {free}»
وإلا: P.bonus.list.push({ id: S.nextId++, day: S.day, kind: 'mgr'|'ra', key: city|country, N: round(N), share, raw: round(raw), cap: round(cap), B, offer, state: 'open' })
ثم (للوكيل): ra.bon0 = ra.paid
```
- البطاقات المفتوحة **تنتهي** بعد `BON.expire` (10) أيام: `state = 'void'` بلا أثر ولا عقوبة. و`P.bonus.list` يُقصّ إلى آخر 24 عنصراً.
- **لا دفع تلقائي أبداً.** ولا تُحسب المكافأة إن `BON.on = false`.

### ج) اختيار اللاعب: `A.bonusGive(S, id, amt)`
```
b = P.bonus.list.find(x => x.id === id && x.state === 'open') ؛ لا ⇒ NO('انتهى هذا الاقتراح')
free = (كما في ب) ؛ lim = min(b.cap, floor(free))
amt  = round(+amt) ؛ يُقبل إن 0 ≤ amt ≤ lim ، وإلا NO('المبلغ أكبر من سقف أجر شهرين أو من الفائض فوق الاحتياطي ({lim})')
amt = 0 ⇒ b.state = 'no' ؛ OK('لا مكافأة هذا الشهر. لا ينقص ذلك من أجره ولا من عمله.')
amt > 0 ⇒ { const c0 = S.ctxCur; S.ctxCur = 'sar'; pPay(S, 'bonus', amt, true); S.ctxCur = c0; }
          f = min(1, amt / max(1, b.B))                                     // نسبة ما أُعطي من المقترح
          e.sk.bon = { till: S.day + BON.growDays, mul: 1 + BON.grow × f, grace: round(BON.grace × f) }
          b.state = 'paid' ؛ b.amt = amt
          news(S, 'كافأتَ {الاسم} بـ{amt} ريال ({pct}٪ من صافي وحدته {N}). يتقدّم أسرع {round(100·BON.grow·f)}٪ ويصبر على تأخر أجره {grace} يوم أكثر لمدة 30 يوماً.', 'good')
```
- **الخيارات في البطاقة** (ask): «أعطه {offer}» (`amt = offer`، الأفضل) · «نصفها {floor(offer/2)}» · «لا مكافأة هذا الشهر» (`amt = 0`). و«يعدّل» = خيار النصف، أو حقل المبلغ في بطاقة الشخص (`10i`/بطاقة الوكيل) بزر «أعطه» يستدعي `bonusGive` بالمبلغ المكتوب في `[0، lim]`. **لا قائمة منسدلة.**
- **الرفض بلا عقوبة:** لا ينقص `late` ولا `xp` ولا شيء.

### د) الأثر (حقيقي، ولمدة 30 يوماً من الدفع)
```
bonMul(e, S)   = BON.on && e.sk && e.sk.bon && S.day < e.sk.bon.till ? e.sk.bon.mul : 1          // full: 1.10 ، half: 1.05
bonGrace(e, S) = BON.on && e.sk && e.sk.bon && S.day < e.sk.bon.till ? e.sk.bon.grace : 0        // full: 2 ، half: 1
```

### هـ) الحدود الشرعية والمالية (يتحقق منها Opus)
- **المكافأة تبرّع اختياري من التاجر، لا جزء من الأجر ولا وعد ملزم:** الأجر المعلوم يبقى كما هو (`managerWage`/`agentWage`)، والمكافأة لا تُشترط عند التوظيف ولا تُعرض كحق. نص البطاقة: «مكافأة منك إن شئت؛ أجره المتفق عليه لا يتغير.» **لا نص ديني ولا حكم جديد** (لا يُكتب «جائز»/«حلال» ولا غيرهما).
- **لا تمس الاحتياطي المحمي ولا الزكاة الواجبة:** `free` أعلاه، ويُعاد حسابه لحظة الدفع (لا من لحظة الاقتراح).
- **وعاء الزكاة** لا يتغير بمعادلة جديدة: المدفوع خرج من النقد كأي مصروف. ولا تُدفع مكافأة من مال الزكاة الواجبة (السطر السابق).
- **لا شرط جزائي ولا مكوّن ضرر** (`actualDamage`/`PEN_PARTS` في 045 بلا تغيير).
- **السقف المالي:** لا يرتفع حد إنفاق أي مدير بالمكافأة، ولا يرتفع أجره.
